# PLOUTO (Stellar Survival)

PLOUTO is a fast isometric wave-survival shooter. You pilot a pod robot in a round arena and shoot waves of enemies. Each wave brings more enemies, elite enemies with special affixes appear from wave 3, and every fifth wave is a boss. Clearing a boss wave opens a reward screen. A run ends when your HP reaches zero.

The game is written in Python with pyglet 2.1.19 (pinned in `requirements.txt`). It runs from source, and `build_all.bat` packs it into a Windows folder with PyInstaller. For the changes in this release, see [CHANGELOG.md](CHANGELOG.md).

## What is in this release

- **Hangar** (title screen button). Ten pod skins. The selected skin recolours the pod, your shots and trails, and the dash afterimage. Nine skins unlock by play: scores, waves, kills, boss defeats or an achievement. The Hangar also lists the 20 achievements, which are checked when a run ends. See `skins.py` and `achievements.py` for the rules.
- **Daily Run** (title screen button). One run per local date. Everyone gets the same seed and the same single mutator for that date. The best score and wave for each date are saved in `progress.json`. Try Again replays the same daily until you return to the menu.
- **Mutators** (opt-in). Five rule changes that you switch on by clicking their chips on the title screen. Each one adds a score multiplier. Glass Cannon, Bullet Hell, Drift, Frenzy and Iron Man. Details are in `WEAPON_SYSTEM_SUMMARY.md`.
- **Power-ups**: Ricochet (bullets bounce once off the edge), Homing (bullets steer to the nearest enemy), Time Slow (enemies run at half speed), Magnet (wider and faster pickup pull), and the rare Drone (a companion that fires for you).
- **Arena events** from wave 4 on, on non-boss waves, on about one wave in three. Meteor Shower, Solar Flare and Nebula Cloud. Each one is telegraphed before it deals damage.
- **Elite affixes**: Volatile, Swift, Shielded, Splitter and Reflector. Splitter elites divide into two copies on death. Reflector elites send back the first shot in every 3-second window.
- **Boss rage**: each boss enters rage once, at 35% HP. Its attack cooldowns are 25% shorter, and each volley gets one more shot.
- **Replay recorder** (`--record`). Saves the inputs of each finished run so it can be replayed.
- **Accessibility options**: reduced motion, a high-contrast HUD, a colour-blind enemy palette, and Screen Shake at Full, Reduced or Off.
- **Audio**: sound effects and music loops, all generated by stdlib-only synthesizers and bundled as WAV files.

## Install

Use Windows with Python 3.12. The `py` launcher must be on your PATH.

```powershell
py -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
```

`requirements.txt` pins every package to an exact version: pyglet 2.1.19, PyInstaller 6.22.3, and the packages they need. Install it with that command. Do not install pyglet by hand.

## Run

```powershell
.\.venv\Scripts\python.exe main.py
```

To record the inputs of each finished run, start with `--record`:

```powershell
.\.venv\Scripts\python.exe main.py --record
```

`run_game.bat` starts the same game. It uses `.venv` when that exists, and otherwise falls back to `py` or `python`.

## Controls

These keys are the ones the code reads in `states.py`, `game.py`, `menu.py` and `rpg.py`.

| Action | Keys and mouse |
| --- | --- |
| Move | `W` or Up, `S` or Down, `A` or Left, `D` or Right. Each key moves along the isometric world axes: W and Up (+x, +y), S and Down (-x, -y), A and Left (-x, +y), D and Right (+x, -y). Keys held together combine. |
| Aim | Mouse cursor. Shots go toward the cursor. |
| Auto-fire | `LMB` toggles it. Auto-fire starts ON for every run. While it is off, the ship does not shoot. |
| Dash | `SPACE`. A 0.15 s dash with 0.15 s of invulnerability. It goes along your movement keys, or toward the cursor when you are not moving. You start with one charge. The base cooldown is 1.5 s, scaled by difficulty and by the Quick Dash reward. |
| Boost | Hold `LSHIFT` or `RSHIFT` while moving or dashing. It needs 12 energy to start, drains 28 per second from a 100 maximum, and recharges at 22 per second when not boosting. While boosting you take 35% less damage, move 1.65 times as fast, and ram enemies for 28 damage. |
| Ultra | `RMB` or `Q`. Needs an Ultra charge and an expired cooldown. |
| Pause | `ESC` pauses. `ESC` again resumes. The pause menu also works with the mouse. |
| Boss reward cards | `1`, `2` or `3` (or the keypad) highlight a card. `ENTER`, keypad Enter or `SPACE` confirm it. Clicking also works. Clearing each boss wave gives a temporary card first, then a permanent one. |
| Game Over | `ENTER`, keypad Enter or `R` retries. `ESC` or `M` goes to the menu. Keys and clicks unlock when the summary reveal ends, after about 1 second (`GAME_OVER_REVEAL_S`). |
| Guide | `LEFT` / `RIGHT`, or `A` / `D`, change page. `ESC` returns to the title screen. |
| Settings | Arrow keys move focus. `ENTER` activates the focused control. On a slider, `LEFT` and `RIGHT` nudge the value and `ENTER` grabs or releases it. `ESC` releases a grabbed slider first, and otherwise returns to the title screen. |
| Hangar | Arrow keys move the skin cursor, or page through achievements. `TAB` switches between Skins and Achievements. `ENTER` selects the highlighted skin, and locked skins are refused. `ESC` goes back. |
| Title screen | Mouse only: Start Game, Daily Run, Guide, Settings, Hangar, Quit. Click a mutator chip to switch it on or off. |

## Settings and saved options

Settings > Music and SFX set the two volumes. They are saved when you leave the Settings screen.

Settings > Accessibility holds three toggles:

- **Motion** (Full / Reduced). Reduced stops decorative animation and screen shake.
- **Contrast** (Normal / High). High adds a dark plate behind each HUD number and brightens the text.
- **Colorblind** (On / Off). Swaps the enemy colours for a palette chosen to keep the enemies apart for deuteranopia and protanopia.

Screen Shake (Full, Reduced or Off) is on the Settings footer. Reduced halves the shake, and Off removes it. Reduced Motion removes it whatever the Screen Shake level is.

Accessibility options and Screen Shake are saved when you change them.

## Audio

- The sound effects and music loops are WAV files in `assets/audio/` (55 files). They are bundled into the build.
- They are generated by two stdlib-only synthesizers. Add `--jobs` to render in parallel. The WAV bytes do not depend on the job count.

```powershell
.\.venv\Scripts\python.exe tools\synth_sfx.py --jobs 4
.\.venv\Scripts\python.exe tools\synth_music.py --jobs 2
```

- If no audio device is available, the game runs silently. `AudioManager` becomes a no-op.

## Replays

`replay.py` records a run's seed, difficulty, skin, mutators and the inputs of every fixed step. It also stores a hash of the game state after each step, so a replay can show where it first stops matching. Recording is off by default. Start with `--record`. Each finished run is written to `replays\last_run.json`, which replaces the previous one.

There is no replay menu and no command-line playback. Playback is a Python API: `replay.load_recording(path)` reads a recording, and `replay.replay(game, recording)` plays it on a game object.

## Tests

The test files are at the project root. Each one prints `[PASS]` lines. A failed check stops the file with a non-zero exit code. Some files print `[SKIP]` lines for checks that need a module which is not in the tree. Run one file at a time:

```powershell
.\.venv\Scripts\python.exe test_mechanics.py
```

Or run them all, stopping at the first failure:

```powershell
foreach ($t in Get-ChildItem test_*.py) { .\.venv\Scripts\python.exe $t.Name; if ($LASTEXITCODE -ne 0) { Write-Error "FAILED: $($t.Name)"; break } }
```

## Build the Windows EXE

Run the one-step build from the project root:

```bat
build_all.bat
```

What it does:

1. Creates `.venv` with `py -m venv .venv` if it is missing.
2. Checks that the three font files exist in `assets\fonts`.
3. Runs `pip install -r requirements.txt` in `.venv`. This installs exactly the pinned versions, so the build uses pyglet 2.1.19. It does not pick newer versions.
4. Deletes earlier build output: `build\kiro2_game`, `dist\Plouto`, and the old zip files. Anything inside `dist\Plouto` is removed, including the save files described below.
5. Runs a syntax check (`py_compile`) on every project Python file, outside `.venv`, `build` and `dist`.
6. Runs `asset_manifest.py`, which checks that every asset the code opens is in the bundle list. `asset_manifest.py --list` prints the asset paths instead.
7. Runs `build_exe.ps1`, which builds with PyInstaller from `kiro2_game.spec`. The spec bundles every file in `assets\fonts` and `assets\audio`.
8. Zips the output to `dist\Plouto.zip`.

The build pauses at the end unless the `NO_PAUSE` environment variable is set.

Outputs:

- Folder: `dist\Plouto\`
- EXE: `dist\Plouto\Plouto.exe`
- ZIP: `dist\Plouto.zip`

Check the build:

```powershell
powershell -ExecutionPolicy Bypass -File tools\smoke_exe.ps1
```

To change the pyglet version, edit `requirements.txt`, rebuild, and run the smoke test.

## Save files

| File | Where it is | What it holds |
| --- | --- | --- |
| `progress.json` | Beside `progress.py`: the project root in a source checkout, or the `_internal` folder in a build | Best wave and score, total kills, bosses defeated, runs played, unlocked skins, selected skin, achievements, and the daily table (best score and wave per date) |
| `user_settings.json` | Beside `main.py` in a source checkout, or beside `Plouto.exe` in a build | Music and SFX volumes, `shake_level` (also written as the older `reduced_shake` flag), `reduced_motion`, `colorblind_palette`, `high_contrast_hud`, and the saved `mutators` selection |
| `high_scores.json` | Beside `score.py`, the same folder as `progress.json` | Up to five entries per difficulty (`easy`, `normal`, `hard`): score, wave, kills, best combo and date |
| `replays\last_run.json` | Beside `replay.py`. Written only with `--record`. | The last finished run's seed, difficulty, skin, mutators, per-step inputs and state hashes |

Save behaviour:

- Loading never raises. A missing file gives the defaults.
- A corrupt file is one that is not valid UTF-8 JSON, or whose top level is not an object. It is renamed to `<name>.corrupt-<n>`, using the first free number, and the game starts with defaults. The bad bytes stay on disk and are not overwritten. If the rename is refused, the file is copied instead.
- Most saves go through a temporary file that is flushed, fsynced and then renamed over the old file. A failed write leaves the old file intact.
- The mutator selection is written by `mutators.py` with a temporary file and a rename, but without fsync. A new `user_settings.json` written this way has no `version` key until the next settings save.
- `progress.json`, `user_settings.json` and `high_scores.json` carry a `version` key. An older file is migrated on load, and a file from a newer build is read as far as possible with its extra keys kept.

In a build, `progress.json` is written inside `dist\Plouto\_internal`, not beside the EXE, and `high_scores.json` is in the same folder as `score.py`. The EXE's `user_settings.json` is beside `Plouto.exe`. `build_all.bat` deletes `dist\Plouto` before it builds, so a rebuild removes these files. Copy them somewhere safe first if you want to keep them.

## Browser build

The repo also has a browser build in `vercel_site/`. `vercel.json` sets `vercel_site` as the output folder and has no build command. `app.js` boots Pyodide and loads the Python modules it lists, such as `py/browser_game.py`, `py/weapons.py` and `py/enemy.py`, from `vercel_site/py/`. The browser build does not run the desktop tools.

To preview it locally, run `run_browser.bat`. It serves `vercel_site` at `http://localhost:8000`.
