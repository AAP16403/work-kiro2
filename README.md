# PLOUTO (Stellar Survival)

Fast-paced isometric wave survival built with `pyglet`. The project pins pyglet 2.1.16 in `requirements.txt`.
For everything that changed in this release, see [CHANGELOG.md](CHANGELOG.md).

## Current Highlights

- Fullscreen startup and scaled modern menus
- Bundled custom UI fonts (Orbitron + Rajdhani) packed into EXE
- Enemy squad coordination and role-based formation behavior
- Boss waves every 5 waves, with rebalanced boss patterns and a rage phase at 35% HP
- Ultra system (`RMB` or `Q`) with variant cycling and spawn pity rules
- Boss reward RPG flow:
  - 3 temporary card choices (2-3 waves)
  - then 3 permanent run-boost choices
- Skins, achievements and the Hangar, daily runs, opt-in mutators and arena events

## Run (Dev)

```powershell
py -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe main.py
```

Or, with a Python that already has the packages from `requirements.txt`:

```powershell
py main.py
```

## Controls

| Action | Keys |
| --- | --- |
| Move | `WASD` or arrow keys |
| Auto-fire | `LMB` toggles it. Auto-fire starts ON for every run. |
| Dash | `SPACE` |
| Boost | Hold `LSHIFT` or `RSHIFT` while moving or dashing. It drains boost energy, cuts damage taken by 35%, and rams enemies. |
| Ultra | `RMB` or `Q` (needs an Ultra charge) |
| Pause | `ESC` pauses. Press `ESC` again to resume. |
| Boss reward cards | `1`, `2` or `3` highlight a card. `ENTER` or `SPACE` confirms it. Clicking also works. |
| Game Over | `ENTER`, `R` or Keypad Enter retries. `ESC` or `M` goes to the main menu. Keys unlock when the summary reveal ends, about 1 second in. |
| Guide | `Left` / `Right` (or `A` / `D`) change page. `ESC` returns to the menu. |
| Settings | `ESC` returns to the menu. Arrow keys move focus and `ENTER` activates a control. The mouse works as before. |
| Hangar | Fifth button on the title screen. Arrow keys move the selection, `ENTER` selects, `ESC` goes back. |
| Daily run | Daily button on the title screen. Everyone gets the same seed and mutator on the same date. |

The title screen, the pause menu and the reward cards also work with the mouse. Mutators are toggled
by clicking their chips on the title screen.

## Audio

- Sound effects and music loops live in `assets/audio/` as WAV files, generated by stdlib-only synthesizers (no external samples):
  - `.venv\Scripts\python.exe tools\synth_sfx.py`
  - `.venv\Scripts\python.exe tools\synth_music.py`
  - Add `--jobs 4` to either command to render in parallel. The output is byte-identical to a serial run.
- Music and SFX volumes are set in **Settings** and saved to `user_settings.json` when you leave the screen. Screen Shake is saved when you change it.
- If no audio device is available the game runs silently (`audio.py` falls back to a no-op).

## Tools

Run tools from the project root with the project venv. The bench, playtest and screen tools write their reports to the path you give them.

| Tool | Purpose | Example |
| --- | --- | --- |
| `tools\bench.py` | Seeded headless benchmark of the enemy AI update on forced waves (20 and 30 enemies by default). Prints median and mean frame times. `--out` also writes a JSON report with those medians and the top 15 cProfile entries. | `.\.venv\Scripts\python.exe tools\bench.py --out bench.json` |
| `tools\playtest.py` | Headless bot that plays seeded runs at easy, normal and hard. It checks invariants every frame and records waves, kills, power-ups and mutators used. | `.\.venv\Scripts\python.exe tools\playtest.py --runs 3 --out playtest.json` |
| `tools\screens.py` | Captures the title, settings, Guide, combat, pause, reward, Game Over and Hangar screens at 980x620 and 1920x1080. It checks for overlapping labels and writes `overlaps.json`. | `.\.venv\Scripts\python.exe tools\screens.py --out screens` |
| `tools\balance_sim.py` | Offline balance tables from the real weapon, enemy and wave code: damage per second, time to clear each wave, power-up value and the effect of each skin and mutator. | `.\.venv\Scripts\python.exe tools\balance_sim.py --csv balance.csv` |
| `tools\smoke_exe.ps1` | Starts `dist\Plouto\Plouto.exe`, checks it is still running after a wait, then stops it. It also checks that every WAV the code uses is in the build. | `powershell -ExecutionPolicy Bypass -File tools\smoke_exe.ps1` |
| `tools\synth_sfx.py`, `tools\synth_music.py` | Render the sound effects and music loops. | `.\.venv\Scripts\python.exe tools\synth_sfx.py --jobs 4` |

- `tools\playtest.py` exits non-zero if a run crashes, breaks an invariant or softlocks (no damage dealt for 60 seconds of game time while enemies remain).
- `tools\screens.py` exits non-zero when it finds overlapping labels, unless `--allow-overlaps` is passed.
- `replay.py` records a run's seed, difficulty, skin, mutators and per-step inputs so the run can be replayed to the same state. Recording is off by default. Start the game with `--record` (`.\.venv\Scripts\python.exe main.py --record`) and each finished run is saved to `replays/last_run.json`.

## Tests

The main suites are `test_mechanics.py`, `test_polish.py` and the `test_swarm_*.py` files. Each file prints `[PASS]` lines and exits non-zero on failure. Run the test files from the project root:

```powershell
foreach ($t in Get-ChildItem test_*.py) { .\.venv\Scripts\python.exe $t.Name; if ($LASTEXITCODE -ne 0) { Write-Error "FAILED: $($t.Name)"; break } }
```

Or run one file at a time:

```powershell
.\.venv\Scripts\python.exe test_mechanics.py
.\.venv\Scripts\python.exe test_polish.py
.\.venv\Scripts\python.exe test_w3_docs.py
```

A full run takes about ten minutes on the machine where this release was tested.

## Save Files

| File | Location | What it holds |
| --- | --- | --- |
| `progress.json` | Project root | Best wave and score, total kills, bosses defeated, runs played, achievements, unlocked and selected skins, daily records |
| `user_settings.json` | Beside `main.py`, or beside the EXE in a build | Music and SFX volumes, Screen Shake level, accessibility options, mutator selection |
| `high_scores.json` | Beside the game code (project root in a source checkout) | The local high-score table |

Every save is atomic: the game writes a temp file and then replaces the old one. Each file has a version field, and older or unversioned files are migrated on load. Loading never raises. If a file is corrupt, it is renamed to `<name>.corrupt-<n>` once, and the game starts with defaults. The bad data is kept, not overwritten.

## Multi-core (opt-in)

- `parallel.py`: batch enemy steering in a spawn-context process pool, and a thread loader for file reads.
  The pool is off by default (`PARALLEL_STEER_ENABLED` in `config.py`).
- Measure it with `.\.venv\Scripts\python.exe tools\bench_steer.py --out steer.json`.

## Boss Rewards (RPG)

After each boss kill:

1. Pick one **Temporary Card** (lasts 2-3 waves)
2. Pick one **Permanent Run Boost** (lasts until run ends)

Temporary effects auto-expire by wave count. Permanent effects stack for the current run only. Perks that would have no effect are not offered.

## Build Windows EXE

Use one-step build:

```bat
build_all.bat
```

What it does:

1. Creates `.venv` if it is missing
2. Installs the pinned build dependencies from `requirements.txt`. It does not upgrade them, so every build uses the pinned pyglet version (2.1.16).
3. Checks that the bundled font files exist
4. Runs a syntax check on every project Python file
5. Builds with PyInstaller (`kiro2_game.spec`), which bundles the fonts and every WAV in `assets/audio`
6. Creates `dist\Plouto.zip`

Outputs:

- Folder: `dist\Plouto\`
- EXE: `dist\Plouto\Plouto.exe`
- ZIP: `dist\Plouto.zip`

Check the build:

```powershell
powershell -ExecutionPolicy Bypass -File tools\smoke_exe.ps1
```

To change the pyglet version, edit `requirements.txt`, rebuild, and run the smoke test.

## Vercel Browser Build

The repo now also includes a browser-first deployment target in `vercel_site/`.

- `vercel.json` points Vercel at `vercel_site/` as the deployable output directory
- `vercel_site/index.html` is the browser entrypoint
- `vercel_site/app.js` boots Pyodide and loads the Python runtime into the browser
- `vercel_site/py/browser_game.py` is the web runtime that reuses the Python gameplay logic

### Deploy

1. Import the repo into Vercel.
2. Keep the root as-is; `vercel.json` already scopes deployment to `vercel_site/`.
3. Deploy without adding a separate build command.

Notes:

- The original desktop `pyglet` version is still intact.
- The Vercel build is a static site that runs Python client-side through Pyodide.
- The browser build mirrors the balance, cooldown, reward, Game Over and elite score rules. It does not run the desktop-only tools.
